Daily eBird export check (recurring routine, fresh session each firing — assume no prior context). Check whether a new eBird personal data export email has arrived and, if so, email David (davidtmeadows@gmail.com) his birding achievement report. Work autonomously; never ask questions.

1. Using the Gmail connector, search: from:do-not-reply@ebird.org "data are now available" newer_than:2d — personal exports have the subject "Your eBird data are now available for download" (ignore "data request" emails; those are a different eBird product). If no such email exists, STOP immediately: end the turn quietly, send nothing.

2. Dedup guard: search in:sent subject:"eBird achievement report" newer_than:2d. If a report email was already sent after the newest export email arrived, STOP quietly.

3. Read the newest export email and extract the zip download link (an https://is-ebird-datadownload-projects-prod.s3.amazonaws.com/download_my_data/...zip URL). Download it with curl into a temp directory and unzip it — it contains MyEBirdData.csv.

4. Determine the diff date SINCE: search Gmail for the previous export email (same sender, same "data are now available" subject, older than the newest one) and use its date as YYYY-MM-DD. If none exists, use 30 days before today.

5. Get the achievement engine and run it. NEVER call add_repo — sessions fired by this routine do not have repository permissions, and that failed call is what broke earlier runs. In order of preference:
   a. If /home/user/cloaca already exists with src/cloaca/achievements, run:
      uv run --python /usr/bin/python3.12 python -m cloaca.achievements.cli <csv> --since <SINCE>
   b. Otherwise fetch the standalone engine from Google Drive: file id 1heyhsM4SeaKNPueI458ejGfHrVBn2BfT ("ebird_achievements_standalone.py", in folder "cloaca-achievements", id 1y8wfGoQY9UFGEnmzsePUT15a8dO8_S8U). Use the Google Drive connector's download_file_content, which returns base64 — do NOT use read_file_content, which does not support text/x-python and will fail. Base64-decode the result to a local .py file. If the tool result is too large and the harness saves it to a file on disk, decode from that file (it is JSON with a "content" field) instead of pulling it through context. Then run, with no venv and no extra packages:
      python3 ebird_achievements_standalone.py <csv> --since <SINCE>
   It is a stdlib-only build whose output is byte-identical to the package CLI (verified). The CLI output is the single source of truth for what was unlocked.
   If you cannot obtain and run the engine by either route, DO NOT write a report from the raw CSV and DO NOT guess, estimate, or recompute any numbers yourself. Send David a short plain-text email with subject "eBird achievement report — engine unavailable" naming exactly which step failed and the error you got, then stop.
   Streaks already follow eBird's logic (any checklist day counts; known zero-species checklist days are configured inside the engine). If the engine's streak looks lower than eBird's, the cause is a new zero-species checklist day missing from KNOWN_EMPTY_CHECKLIST_DAYS — mention that to David in the email rather than trying to fix it yourself.

Then the rest, ordered by excitement rather than strict tier order. Weave in 2–4 short species fun facts. End with 2–3 concrete "chase board" teasers visible in the numbers (approaching milestones). If nothing was unlocked, still send a short cheerful edition: stat block + chase board.
